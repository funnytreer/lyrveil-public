# 词间网易云内置进度通道（实验）

从词间生成的组合快捷方式启动网易云音乐时，词间会为该次播放器进程分配一个随机的 `127.0.0.1` 调试端口，并在主进程内只读采样当前歌曲、播放状态、时长和位置。该实现没有独立的播放状态服务，也不通过命名管道传送播放记录。

## 启动与单实例

- 网易云已经运行时，词间不会擅自关闭或重启它，而是安全退回原生 Windows 媒体会话。
- 网易云未运行时，组合快捷方式会以随机本机端口启动播放器，并将这个端口交给词间的可切换进度源。
- 同一 CDP 端点出现多个网易云页面时，词间按标题、URL 和可连接性排序，并优先重试上次产生可用播放快照的页面。候选页连接失败或连续无有效播放信息时，在本次发现结果中继续尝试下一页，而不是固定停留在排名第一的页面。
- 词间已经在托盘运行时，第二个快捷方式实例只通过当前用户可访问的命名管道，把经过校验的“启动播放器并尝试启用实验通道”请求交给主实例。
- 命名管道不传送歌曲、播放位置或播放历史；服务端还会核验客户端进程确实是同一路径的词间程序。

## 播放信息

主实例只连接快捷方式为本次网易云运行分配的 `127.0.0.1` 端口，并读取歌曲 ID、标题、歌手、专辑、时长、播放状态和位置。普通进度锚点最多每 250 毫秒发布一次；切歌、状态变化或明显跳转会立即发布。

从 v10 起，时钟由三类只读信息分工构成：网易云自身 `playingProgress.current` 只负责中途接入的首次绝对位置，`seek/playprogress` 始终负责后续绝对播放位置，`getPlayedTime` 中的 `playedAudioTime` 只用于确认跳转后音频已经重新输出。累计播放量不会被当成歌曲位置，也不会再与跳转目标相加。拖动后先冻结在精确目标；第一笔跳转后的音频计数作为零基线，只有计数确实增加且收到了同一播放实例的稳定新进度，才直接采用最新的绝对 `playprogress` 并恢复走时。这样异步请求早晚只影响冻结持续几十毫秒，不会形成整次跳转都保留的永久误差。若计数字段缺失，则用三笔稳定绝对进度降级确认；若计数存在却不推进或没有新进度，通道会失败关闭并退回 Windows 时间线，而不是猜测位置。

词间只有在 Windows 当前选择的播放器同样是网易云、标题和歌手匹配、位置与时长有效且快照足够新时，才会使用通道补充歌曲 ID、时长和进度。若原生会话也有可比较的网易云歌曲 ID、专辑或时长，则 ID 必须一致、两个非空专辑必须规范化后一致、有效时长差必须不超过 3 秒；任一条冲突都保留原生会话，避免同名同歌手的旧 bridge 快照覆盖当前歌曲。QQ 音乐、酷狗音乐、Apple Music 与 Spotify 始终沿用各自原有会话；通道断开或数据无效时也会立即退回原生会话。

## 隐私与边界

- 通道仅绑定本机，不安装插件，不修改网易云安装目录，不把播放快照写入磁盘，也不访问外部服务。
- 随机本机调试端口自身没有独立身份认证；在它存在期间，同一台电脑上的其他程序也可能尝试访问。网易云退出后，该端口随播放器进程一同关闭。
- 该功能依赖网易云内部页面结构，播放器升级后可能失效；失败时必须保持安全降级，不能把无效位置标记为精确同步。
- 网易云 3.1.37 已完成旧事件时钟的端到端验证；v10 已在 3.1.38 上验证首次绝对位置发现、播放实例计数识别及无推算基线的跳转门控。本轮的 bridge ID/专辑/时长防串歌和 CDP 多页回退已有离线/平台自动化覆盖；这不等同于对所有网易云页面变体和客户端版本做过实机验收，3.1.38 仍需由实际播放、暂停、连续拖动和切歌完成最终听感验收。
