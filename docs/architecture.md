# 初版架构

```text
受支持的 Windows 音乐播放器
    │ GSMTC 事件                   网易云实验性本机进度
    ▼                                      │
音乐播放器白名单 ──► GsmTcPlaybackService ─┴─► EnhancedNetEasePlaybackService
                                                  │
                                                  ▼
                                   PlaybackSnapshot + 同步质量 + 本地时钟
                                                  │
    曲目变化 ──► LyricsResolver ◄──── 本地缓存 / 手动 LRC / 导入 LRC
                    │
                    ├── LRCLIB
                    ├── 网易云音乐
                    ├── QQ 音乐
                    └── 酷狗音乐
                    │
                    ▼
          身份、版本、专辑、时长与歌词质量评分
                    │
                    ▼
正则显示过滤 ──► LyricTimeline ──► 当前句 / 第二句 / 逐字或逐行进度
                    │
                    ├── OverlayWindow（点击穿透、经过隐藏）
                    ├── QuickPanelWindow（高频调节）
                    └── SettingsWindow（完整设置）
```

关键边界：播放器适配、歌词提供、歌词解析和 UI 分层独立。新增某个播放器适配器或歌词源时，不需要修改桌面悬浮窗。

歌词解析器通过结果对象区分可显示文档和保存失败，通过来源结果保留网络、超时及异常响应摘要。文档一旦可用便通知控制器呈现；持久化和缓存升级的后续结果仍必须通过当前曲目及操作代际检查。缓存读写和目录维护共享异步锁，最终文件只在临时文件完整写入后替换。

自动匹配与手动候选浏览采用不同的请求规模和总等待预算。候选身份优先使用来源歌曲 ID，没有 ID 时保留专辑；词模型的可选结束时间通过增强 LRC 空片段标签保存，旧歌词没有结束时间时继续插值。

设置的防抖保存、位置立即保存和失败退避由 `SettingsPersistenceService` 管理；选词窗口共用 `LyricsCandidateViewModel`。帧刷新和鼠标检测按播放及可见状态启停，应用样式与界面回归共用 `Themes/SharedStyles.xaml`。

GSMTC 会话先按来源应用过滤。当前白名单为 QQ 音乐、网易云音乐、酷狗音乐、Apple Music 和 Spotify；浏览器即使成为 Windows 的当前媒体会话也会被跳过，并继续选择其他正在播放的受支持音乐播放器。

播放层以 `SessionsChanged`、`CurrentSessionChanged`、`PlaybackInfoChanged`、`MediaPropertiesChanged` 和 `TimelinePropertiesChanged` 为主触发更新。后台仅做 1–10 秒的自适应安全复查，并每 30 秒重新枚举一次会话自愈；不会固定每 0.5 秒反复解绑和订阅全部播放器。

多会话仲裁使用不可被弱信号累加翻转的分层优先级：近期实际出声 > 播放器明确上报 `Playing` > 可用时间线 > Windows 当前会话。Core Audio 样本同时保留“当前出声”和“近期出声”两组结果：后者只用于短时稳定会话选择，前者才可修正本帧播放状态，避免暂停后的尾音把状态改回 `Playing`。

时间线分为四种质量：播放器或经过验证的内置进度通道提供有效锚点时为 `Reported`；普通本地时钟推进为 `Estimated`；网易云增强通道刚中断、但仍从最后可靠增强锚点续时为 `EnhancedEstimated`；没有可靠进度时为 `Unavailable`。网易云内置通道只在 Windows 当前会话同样识别为网易云、歌曲标题和歌手匹配且快照足够新时补充歌曲 ID、时长与位置；当原生会话也提供歌曲 ID、专辑或有效时长时，增强快照必须分别一致（时长差不超过 3 秒）才能合并，否则保留原生结果。CDP 端点暴露多个页面时按可用性排序，上次产生有效快照的页面优先；页面连接失败或连续不产生可用播放信息时，在同一次发现中继续尝试下一候选。若增强会话在 Genres 中发布 `NCM-{ID}`，播放层也会规范化为歌曲 ID，歌词源优先直接读取对应歌曲。

Apple Music 的 seek 过渡不使用全局时间戳粗暴排序所有播放器快照。新旧判断只在同一 Apple Music 来源、会话和可比较的歌曲 ID 内进行；目标已确认后再到达的 seek 前位置群保持隔离，不覆盖当前渲染锚点。

播放曲目的宽松身份仍用于容忍小范围元数据抖动；歌词异步操作另用包含规范化歌名、歌手、专辑和取整时长的严格身份。这使标准版、Live 版或不同专辑版本可以取消彼此的旧搜索/导入回填，避免异步结果串版。

完整的产品状态、界面规格、隐私边界和验收要求见 [产品设计规范](product-design-specification.md)。

## 启动生命周期

- 完整应用不注册 Windows 登录自启动；可选监听器以 `--player-monitor` 无界面运行。
- 组合快捷方式保留播放器名称和图标，以 `--companion <player.exe>` 启动应用。
- 应用保证单实例；已有词间实例时，组合快捷方式会通过仅限当前用户的本机通道，把播放器启动及网易云实验进度通道配置交给主实例。
- 网易云进度通道每 3 秒在后台重新发现一次，仅连接进程明确声明的本机端口；晚启动、重启换端口或一次发现失败不会永久失联。发现串行执行，退出时取消并等待结束。端口发现本身不重启播放器。
- 用户启用 `AutoRepairNetEaseSync` 后，组合模式中的网易云入口每 10 秒自动检查：维护独立命名的桌面入口，并修复当前用户普通桌面及已固定任务栏快捷方式。只接受已知的网易云目标和空参数，保留自定义命令，不改公共桌面；原链接先备份。后台监听器即使在主窗口关闭时也可维护入口。
- 已运行的网易云缺少通道时，`NetEaseRecoveryPolicy` 要求新鲜的网易云暂停状态连续约 8 秒，且没有更新活动，才允许恢复一次。再次核对进程 ID、启动时间、路径与暂停状态后，仅停止同一路径的网易云主进程和子进程，并等待旧实例退出后重新组合启动。播放中、未知/过期状态、其他播放器和已有有效原生时间线均不触发恢复。
- 恢复失败后不因新进程 ID 或短暂退出反复重启；通道恢复或播放器真正关闭至少 15 秒后才重新允许。恢复日志保存在本机 `netease-recovery.log`，限约 64 KiB。设置页说明暂停重开可能重置播放位置。
- 组合伴随实例先做短重启探测；检测到播放器更新活动时最多等待 5 分钟，否则快速关闭。
- 监听器按设置中的播放器白名单观察进程，并以 `--monitor-managed` 按需启动完整应用。
- 监听器发起启动后等待最多 4 秒确认主实例锁；启动失败或主实例短时退出时按 2、4、8 秒递增并封顶 30 秒退避，稳定运行 30 秒后重置失败次数；关闭监听与网易云自动维护后无界面循环自行退出。
- 设置或快速面板打开期间暂停自动退出，避免配置时窗口消失。
- 应用退出时先停止定时器，再将内存中最新监听配置追加到有序注册队列。设置保存、注册、IPC、窗口、播放服务、歌词来源和单实例锁分别清理并记录失败；任一步骤异常不阻止其他步骤和最终退出。
